# Governance

OSEL is a specification project maintained in this repository by the
OpenReciprocal organization. It is not a software product, a foundation, or
a certification body.

## Maintainers

Maintainers are the people with commit access to the default branch of
`OpenReciprocal/open-source-evolution-license`. The initial Version 0.1 text
and the original repository overview were committed by lemonhub-io.

Maintainers may appoint additional maintainers. A maintainer who is inactive
for a long period may be removed by the remaining maintainers. This file
will be updated when the set of maintainers changes.

## What is normative

`LICENSES/OSEL-0.1.txt` is the license of record for Version 0.1. Its
Markdown rendering is normative only where it reproduces that text.

`LICENSES/OSEL-0.2-draft.txt` is a published discussion draft. It is the
text a project applies if that project chooses Version 0.2. It does not
change the meaning of 0.1, and the maintainers have not adopted it as a
successor that retires 0.1. If the plain text and
`LICENSES/OSEL-0.2-draft.md` differ, the plain text controls.

Everything under `docs/`, including the evolution essay, drafting notes, the
OSD checklist, the compatibility list, and translations, is explanation. It
cannot amend either license text. The FAQ and this file are explanation as
well.

## How decisions are made

The project prefers consensus on the issue tracker.

- Editorial changes to documentation, examples, and translations may be
  merged by a maintainer after review.
- A change to operative license text requires an issue, time for comment, and
  a new version file. It is not edited into a version that has already been
  published, except to correct a copying error that does not change meaning.
  The relocation of the non-operative drafting notes out of the 0.1 file was
  that kind of editorial separation.
- If consensus does not form, the maintainers decide. A decision to leave the
  text unchanged is a valid outcome.
- No single adopted project, and no downstream user, gets a private variant
  called "OSEL" with different terms. Variants need their own name.

The project does not take a vote of users as a substitute for the text.
Adoption is voluntary.

## OSI and other outside bodies

Only the maintainers may submit OSEL for OSI review, and only after the
roadmap conditions are met. A contributor must not file the draft with OSI,
or with another license registry, in the project's name.

A submission, if it happens, will point at a tagged version and at the open
issues that were closed to produce it. Approval is OSI's decision. This
repository will not predict it.

## Conduct and licensing of contributions

Discussion follows [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md). Contribution
terms are in [CONTRIBUTING.md](CONTRIBUTING.md). There is no separate
contributor license agreement. The CC0 dedication for license-text
contributions and the CC-BY-4.0 license for documentation are the grants the
project relies on.

## Trademarks

The project claims no registered trademark in this file. The names "Open
Source Evolution License" and "OSEL" are used to identify the draft.
Nominative use is expected. A modified license that changes the grants must
not be presented as OSEL Version 0.1.
