# OSEL 0.2 — discussion draft

The canonical text is [`OSEL-0.2-draft.txt`](OSEL-0.2-draft.txt). This page
is a reading map. If the two differ, the plain text controls.

This draft does not amend Version 0.1. It is not OSI-approved. The essay
that states the idea is [`docs/evolution.md`](../docs/evolution.md).

## What changed from 0.1, as a mechanism

Version 0.1 named the step Replacement and tested it by asking whether one
license's obligations strictly contain another's. This draft names the step
Evolution and tests it with the Evolution Menu in Section 1.10 and the
target rule in Section 1.11.

| 0.1 | 0.2 discussion draft |
| --- | --- |
| Replacement, Section 5 | Evolution, Section 5 |
| Strict-superset sentence | Menu: attribution, source, patents, names, changes |
| `LICENSE-REPLACEMENT.md` in a root directory | `EVOLUTION.md`, or an equally prominent notice |
| Sublicense of the Section 2 rights | Further grants only under this License or a valid Evolution |
| Patent election that could be read as widening the original grant | Section 3.4: the original grant neither shrinks nor grows |
| Undefined Project, Affiliate, Contribution, Copyright Holder | Defined in Section 1; each copyright holder licenses only their own work |
| Contributor confirms non-infringement of all third-party rights | Section 4.1(c) confirms authority and originality |
| Irrevocable, also terminated on breach | Section 2 defines irrevocable as no withdrawal at will |
| Entire agreement, with no room stated for a replacement | Section 9.3 keeps a valid Evolution inside the terms |
| A failed replacement left implicit | Section 5.8: a failed step is not an Evolution |

The Menu is the part that is new as an idea, not only as cleanup. It states,
in this license's own words, which added duties a descendant may take on.
A list of other licenses' names is a different design, and this draft does
not use one.

## How to read a hard sentence

Section 1.11(c) admits every added duty only if it sits on the Menu.
The next sentence stops that rule from rejecting share-alike for doing the
thing share-alike exists to do: the descendant may no longer be offered
under a thinner license. That withdrawal counts as carrying out a Menu duty,
not as an off-menu restriction.

Section 5.1 and Section 5.2 together are the other hard pair. The step is
available to every recipient, and only when they ship a modified version.
An ancestor, and a verbatim copy, stay under this draft.

Section 3.4 is the patent boundary. The recipient who takes the step may
pass on patent rights that recipient holds. The step is not a power to
rewrite another person's patent promise.
